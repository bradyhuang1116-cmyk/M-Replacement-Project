## 一、项目目标与需求

### 1.1 项目概述

本项目为三菱电机图纸批量编号替换系统，用于自动识别工程图纸上的零件编号，并在编号前添加"H"前缀（如 `YA026D941` → `HYA026D941`）。

### 1.2 功能需求

| 功能 | 说明 |
|------|------|
| **矢量PDF替换** | 对矢量PDF文件，直接提取文本层进行精确替换，不依赖OCR |
| **OCR图像替换** | 对扫描版PDF、TIF、JPG等图像文件，通过OCR识别编号后进行像素级替换 |
| **多区域检测** | 自动检测三个关键区域：红框（材料编号列）、绿框（右下角编号）、橙框（左上角编号） |
| **工厂注意检测** | PP-DocLayoutV3 布局检测，在红/绿/橙框以外的区域识别编号 |
| **四方投票校验** | 绿框、橙框、红框、文件名四方交叉校验，确保替换准确性 |
| **混合OCR引擎** | 红框用 PaddleOCR v5（结构定位），绿/橙框+替换用 VLM (PaddleOCR-VL-1.5) |
| **一键替换** | 上传文件后直接执行检测+替换，无需预览确认 |
| **画布内缩** | 替换后画布整体内缩 2.5%，四周填白 |
| **批量处理** | 支持同时上传多张图纸批量处理 |

### 1.3 替换规则

- 识别以指定首字母开头的编号（默认 X、Y），总长度 ≥ 7 字符
- 在编号前添加前缀 `H`
- 红框区域：逐单元格识别替换，支持删除线检测
- 绿框/橙框：四方投票确定编号后整体替换

### 1.4 输出规则

| 输入格式 | 处理模式 | 输出格式 | 输出文件夹 | 文件命名 |
|----------|----------|----------|------------|----------|
| 矢量PDF | 直接文本替换 | PDF | `output/latest/vector/` | `H` + 原文件名 + `.pdf` |
| 扫描PDF/TIF | OCR识别替换 | TIF | `output/latest/ocr/` | `H` + 原文件名 + `-R.tif` |
| JPG/PNG | OCR识别替换 | 原格式 | `output/latest/ocr/` | `H` + 原文件名 + `-R` + 原扩展名 |

## 二、本地部署指南

### 2.1 系统要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10/11 或 Linux |
| Python | 3.11 或 3.12（**不支持 3.14**，PaddlePaddle 不兼容） |
| CPU | 4核以上 |
| 内存 | 16 GB 以上（混合模式需同时加载 v5 和 VLM） |
| 磁盘 | 约 5 GB（含模型文件） |
| GPU | **NVIDIA GPU + CUDA 必需**（VLM 推理需 GPU，约 12GB VRAM） |

### 2.2 安装步骤

#### 第一步：克隆项目

```bash
git clone https://github.com/bradyhuang1116-cmyk/Mitsubishi-Electric-Drawing-Replacement-Project.git
cd Mitsubishi-Electric-Drawing-Replacement-Project
```

#### 第二步：创建 Python 虚拟环境

```bash
# conda 方式（推荐）
conda create -n mitsubishi python=3.12
conda activate mitsubishi
```

#### 第三步：安装依赖

```bash
pip install -r requirements_local.txt
```

依赖清单：
| 包名 | 版本要求 | 用途 |
|------|----------|------|
| paddlepaddle | ==3.0.0 | OCR推理引擎（PaddleOCR v5） |
| paddlex | >=3.0.0 | PP-DocLayoutV3 布局检测 |
| PyMuPDF | >=1.23 | PDF解析与渲染 |
| opencv-python-headless | >=4.8 | 图像处理 |
| Pillow | >=10.0 | 图像读写 |
| numpy | >=1.24 | 数值计算 |
| tqdm | >=4.65 | 进度条 |
| gradio | >=4.40.0 | Web界面 |
| requests | >=2.28 | VLM HTTP 调用 |

#### 第四步：配置 VLM OCR 引擎（vLLM 服务器）

VLM（PaddleOCR-VL-1.5）通过 vLLM HTTP 服务器提供服务：

1. 安装 vLLM 并下载模型（参考 `vllm_config.json`）
2. 启动 vLLM 服务器：
```bash
start_vllm_server.bat
```
3. 默认监听 `http://localhost:8080/v1`，模型名 `PaddleOCR-VL-1.5-0.9B`
4. 配置可在 `config.py` 中修改 `VLLM_BASE_URL` 和 `VLLM_MODEL_NAME`

#### 第五步：验证安装

```bash
python -c "import paddleocr; import fitz; import gradio; print('依赖安装成功')"
```

### 2.3 启动服务

```bash
python web_app.py
```
启动后访问 http://localhost:7860

### 2.4 首次运行

首次启动时会自动下载以下模型：

| 模型 | 大小 | 用途 |
|------|------|------|
| PP-OCRv5_server_det | ~200 MB | 文字检测（红框定位） |
| PP-OCRv5_server_rec | ~200 MB | 文字识别（红框定位） |
| en_PP-OCRv5_mobile_rec | ~50 MB | 英文识别（红框验证） |
| PP-DocLayoutV3 | ~100 MB | 布局检测（工厂注意区域） |

下载位置：`C:\Users\<用户名>\.paddlex\official_models\`

VLM 模型（PaddleOCR-VL-1.5）需单独安装，通过 vLLM 服务器加载。

### 2.5 使用流程

1. **上传文件** — 支持 PDF、TIF、TIFF、JPG、JPEG、PNG
2. **选择检测首字母** — 默认 X、Y，按需勾选
3. **点击"开始替换"** — 系统自动检测区域并执行替换
4. **替换完成** — 结果显示在右侧 Gallery，输出文件保存在 `output/latest/`

### 2.8 常见问题

**Q: 启动时报 `paddlepaddle` 安装错误？**
A: 确认 Python 版本为 3.11 或 3.12，不支持 3.14。

**Q: VLM 未响应？**
A: 确认 vLLM 服务器已启动（`start_vllm_server.bat`），检查 `http://localhost:8080/v1/models` 是否返回模型列表。

**Q: GPU 显存不足？**
A: 混合模式峰值约 12GB VRAM。如果 GPU 显存不足，需要更换显卡或分时加载模型。

**Q: 首次启动卡在模型下载？**
A: PaddleOCR/PaddleX 需下载约 500 MB 模型文件，请确保网络通畅或手动下载。

**Q: 替换后字体不对？**
A: 确认 `fonts/DingLieSongKeTi/dingliesongtypeface20241217-2.ttf` 文件存在。
