# 云端化改造变更记录

> 项目：m-replacement-project
> 目标：部署到无显卡机器，推理调用从本地切换为百度 AIStudio 云端 API（引擎不变：v5 仍是 v5、VL 仍是 VL，仅调用方式改为调云端）。支持在前端运行时切换本地 / 云端模式。

## 二、Bug 修复

本地模型与云端 API 在结果格式、坐标体系、文本切分上存在差异，导致云端模式下出现以下问题，均已修复：

### 1. 识别结果为空（绿框 / 橙框 / 工厂注意区全部检测不到）
- **区别**：本地模型返回的检测结果直接是 `dt_polys / rec_texts / rec_scores` 字段；云端 API 把这些包在 `spotting_res` 里，字段层级和命名不同。
- **改动**：在 `vlm_ocr_engine.py` 的结果解析函数中增加对云端 `spotting_res.rec_polys / rec_texts` 结构的适配，使云端返回能正确解析成统一的内部格式，下游检测逻辑无需改动。

### 2. 替换位置偏移（编号框整体偏左、偏小）
- **区别**：本地模型输出归一化坐标（与图像实际尺寸无关，框位置天然正确）；云端 API 输出绝对像素坐标，且发送前会对超过约 100 万像素的图做内部缩放，返回坐标基于缩放后图像，未还原回原图。
- **现象**：以橙框编号为例，本地框为 `x=539, w=402`，云端误为 `x=327, w=243`（位置左偏约 210px、宽度仅约 0.6 倍）。
- **改动位置**：`modules/vlm_ocr_engine.py` 的 `VlmOcrEngine.predict()` 云端分支。
- **改动内容**：原先直接把整图交给云端、用返回坐标，未处理云端内部缩放。改为发送前自己把图缩到 ≤1MP 并记录缩放比 `_api_scale`，收到坐标后乘 `1/_api_scale` 还原回原图：
  ```python
  # 改后（核心）
  if total > _max_px:
      _api_scale = (_max_px/total)**0.5
      send_img = pil_img.resize((int(ew*_api_scale), int(eh*_api_scale)))
  result = self._paddleocr_api_call(send_img, "spotting")
  if _api_scale != 1.0:
      inv = 1.0/_api_scale
      item["polygon"] = [[int(pt[0]*inv), int(pt[1]*inv)] for pt in polygon]
  ```
- **结果**：橙框云端坐标由 `x=327,w=243` 还原为 `x=540,w=402`，与本地 `x=539,w=402` 对齐。

### 3. 替换框偏大、遮挡相邻文字（工厂注意区）
- **区别**：同一小图，本地模型输出紧凑编号框；云端 API 倾向带空格、框较松，会把相邻标点/字符的笔画一并框入。
- **现象**：工厂注意区两个编号，本地框宽 `397 / 319`，云端偏大为 `442 / 419`，替换涂白盖住右侧相邻字。
- **改动位置**：`modules/factory_note_pixel.py` 的 `_snap_to_runs()`（编号框的笔画吸附逻辑）。
- **改动内容**：原先取所有与候选区重叠的笔画段的最小左、最大右边界（会把两端相邻字符笔画一起包进，还额外放宽了约一个字宽）：
  ```python
  # 改前
  new_left  = min(rs for rs,_ in overlapping)
  new_right = max(re_ for _,re_ in overlapping)
  new_left  = max(new_left,  left_col - char_w)   # 还往外放宽
  new_right = min(new_right, right_col + char_w)
  ```
  改为按字间隙（>1.2 字宽）把笔画段聚类，只保留跨度最大的连续簇（编号主体），剔除两端孤立笔画，且不再外扩：
  ```python
  # 改后
  clusters 按 gap_thresh=max(char_w*1.2,14) 切分 overlapping
  best = max(clusters, key=簇跨度)
  new_left  = max(min(best左), left_col)
  new_right = min(max(best右), right_col)
  ```
- **结果**：工厂注意区框由 `442 / 419` 收紧到 `415 / 380`（本地 `367 / 296`），遮挡缓解到可接受范围。
- **注意**：此收紧逻辑仅在云端模式生效；本地模式下 `_snap_to_runs` 保持原 min/max + 外扩逻辑，本地画框规则完全不变。

## 三、模式开关（本地 / 云端运行时切换）

- **接口**：`GET /api/v1/mode` 读当前模式，`PUT /api/v1/mode`（body `{"mode":"cloud"|"local"}`）切换。
- **行为**：切换仅改运行时 `config.VLM_PROVIDER`，**不持久化**——进入前端默认云端，重启后回到默认云端。
- **前端**：Dashboard 右上角 run 按钮左侧的开关（云端 ☁ / 本地 💾），运行中禁用，只能在开始替换前切换。
- **切换时重置引擎缓存**（关键）：切模式必须清掉所有模块各自缓存的引擎，否则切换后仍用旧引擎。涉及三处：
  - `vlm_ocr_engine._engine_instance`
  - `region_detector._v5_cloud_engine` / `_v5_cache`
  - `factory_note_pixel._vlm_engine` / `_v5_engine`（工厂注意区独立缓存，曾因漏清导致切到本地后框尺寸仍是云端的）
- **docker_manager 动态读 provider**：`ensure_vlm_ready` 等改为运行时读 `config.VLM_PROVIDER`（原先是 import 时快照），否则切到本地后不会自动拉起本地容器。
- **切本地后点"开始替换"**：worker 的 `ensure_vlm_ready` 自动拉起本地 vLLM 容器并预热（本地模式固有流程，需本地 Docker + GPU）。

## 四、已知差异（可接受）

- 工厂注意区框比本地略宽，遮挡已缓解到可接受范围。
- 云端少识别料号列小写 `x` 开头编号（云端无预选识别步骤）。

## 五、默认与回滚

- 默认云端（`VLM_PROVIDER=paddleocr_api`），进入前端即云端模式。
- 运行时切本地：前端开关，或 `PUT /api/v1/mode {"mode":"local"}`（不持久化，重启回云端）。
- 永久切本地：`.env` 设 `VLM_PROVIDER=vllm`（需本地 Docker 容器 + GPU）。
